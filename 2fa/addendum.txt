2fa plugin - File permissions addendum
=======================================

You only need this page if setup fails with a permissions error, such as:
  "Could not save the two-factor data. Check that plugins/2fa/data is writable."
  or the language editor (Plugins -> 2fa -> Language) cannot save changes.

On most hosted web servers, the plugin works with the default permissions
after you copy the folder into plugins/. Do nothing special in that case.

Permissions are only a concern on servers where the web server user
(often www-data, apache, or nginx) cannot write to the plugin's folders.


1. Find the web server user
---------------------------
Replace www-data below with the user that runs PHP on your server. Check
with phpinfo(), or look at the owner of an existing CMSimple_XH folder:

    ls -ld /var/www/html/plugins/*

Adjust /var/www/html/plugins if your installation path is different.


2. Set the permissions
----------------------
Run as root or with sudo:

    cd /var/www/html/plugins
    sudo chown -R www-data:www-data 2fa
    sudo find 2fa -type d -exec chmod 755 {} +
    sudo find 2fa -type f -exec chmod 644 {} +

    # Language editor: languages/ must be writable by the web server user
    sudo chown -R www-data:www-data 2fa/languages
    sudo chmod 755 2fa/languages
    sudo chmod 644 2fa/languages/*.php

    # Secret and rate-limit data: only the web server user may read or write
    sudo chown -R www-data:www-data 2fa/data
    sudo chmod 700 2fa/data

    # After the first successful setup:
    sudo chmod 600 2fa/data/twofa.php


3. Expected modes
-----------------
    plugins/2fa/                              755   (deploy user or www-data)
    plugins/2fa/*.php, version.nfo,
      LICENSE, README.md                      644   (deploy user or www-data)
    plugins/2fa/js/                           755
    plugins/2fa/js/qrcode.js                  644
    plugins/2fa/languages/                    755   (www-data)
    plugins/2fa/languages/*.php               644   (www-data)
    plugins/2fa/data/                         700   (www-data)
    plugins/2fa/data/.htaccess, index.php     644   (www-data)
    plugins/2fa/data/twofa.php                600   (www-data, created by PHP)
    plugins/2fa/help/                         755   (deploy user or www-data)
    plugins/2fa/help/help.htm                 644   (deploy user or www-data)


Why
---
PHP must be able to write to data/ to save the secret and the rate-limit
state. It must also write to languages/ if you edit translations in the
language editor. Nothing else needs write access for www-data.

The help/ folder only needs to be readable by the web server, so it needs
no write access. The commands in step 2 already cover it. The help page
opens from the Plugins -> 2fa backend, and the web server must be able to
read help/help.htm for the page to load.

Never use 777. It makes the secret readable and writable by every user on
the server.


4. Nginx: protect the data/ folder
---------------------------------
Nginx ignores .htaccess files, so the data/ folder is not blocked from web
access automatically. If your server runs Nginx, add this block to your
server configuration, then reload Nginx:

    location ^~ /plugins/2fa/data/ {
        deny all;
    }

Apache users do not need this. Apache uses the data/.htaccess file.
